# The BombayChitra integration layer

[BombayChitra](https://github.com/AmmaarBakshi/BombayChitra) is Nosferatu's map. Nosferatu does not have a map
pipeline of its own and does not use Google Maps: every tile, style, road and path it shows or reasons about comes
from BombayChitra's published data. The `:bombaychitra` module is the only code that knows BombayChitra's formats;
the tracking engine sees a plain `RoadNetwork` interface, and the app sees a style string and an adapter.

Why this layer exists, and what else was considered, is in [integration-assessment.md](integration-assessment.md).

## What is used from BombayChitra

| BombayChitra artefact | Where it comes from | How Nosferatu uses it |
|---|---|---|
| `bombaychitra.pmtiles` (vector tiles, ~96 MB) | `data-latest` GitHub release, checked against `SHA256SUMS` | Read in place by MapLibre Native (`pmtiles://file://…`). Downloaded in the app once; works offline. |
| `styles/dark.json`, `styles/light.json` | Generated by BombayChitra's web build, fetched from `bombaychitra serve` | Shipped unmodified in `app/src/main/assets/bombaychitra/styles/`. Only the `bc` source and glyph URLs are rewritten at runtime. |
| Noto Sans glyph PBFs | BombayChitra's `web/public/fonts` | Shipped in `app/src/main/assets/fonts/`, loaded via `asset://fonts/{fontstack}/{range}.pbf`. |
| `routing` + `meta` tables of `bombaychitra.db` | `data-latest` release or a local BombayChitra build | Copied byte for byte into `graph.db` (~14 MB), shipped in the APK, decoded by `BombayChitraGraph`. |

Prepare the assets with `scripts/bombaychitra_assets.py` (see the README). The styles and fonts are committed;
`graph.db` is not (it is data, ODbL) and is generated before building.

## Public API

All in package `dev.nosferatu.bombaychitra`.

### `BombayChitraAdapter`

Nosferatu's single entry point for map questions. It implements the engine's `RoadNetwork` and adds two questions
that can each answer "I don't know".

```kotlin
val adapter = BombayChitraAdapter.load(blobSource)   // ~3 s on a laptop JVM for the whole MMR

adapter.covers(p)                     // inside BombayChitra's region?
adapter.candidates(p, radiusM = 30.0) // walkable ways near p, nearest first, with the projected point and bearing
adapter.networkDistance(a, b, maxM)   // walking distance along the network, or null if not reachable within maxM

when (val l = adapter.lookup(p)) {
    MapLookup.OutsideCoverage -> …     // no map data here
    MapLookup.NoWayNearby -> …         // inside the region, nothing walkable within 30 m: maybe an unmapped path
    is MapLookup.OnWay -> l.name       // one clear nearest way
    is MapLookup.Ambiguous -> …        // parallel roads, a junction: the map alone can't decide
}

adapter.plausibleMove(a, b, elapsedS) // could this movement have happened on foot along the network?
```

Only ways that BombayChitra marks as open to pedestrians are candidates (`seg_access` foot bit). Steps, bridges and
tunnels are flagged on each `RoadSegment` so the matcher can treat them with care (a GPS fix under a flyover is not
evidence for the flyover).

### `BombayChitraStyle`

```kotlin
BombayChitraStyle.offline(template, pmtilesUri, glyphsUri)           // BombayChitra's style, local tiles and glyphs
BombayChitraStyle.hidingSourceLayers(style, BombayChitraStyle.QUIET_HIDDEN) // hide places + house numbers (run map)
BombayChitraStyle.pmtilesFileUri(path)                                // "pmtiles://file:///…"
BombayChitraStyle.serverStyleUrl(baseUrl, MapTheme.Dark)              // for a running BombayChitra server
```

`offline()` throws `UnsupportedStyleException` if the style does not have BombayChitra's single `bc` vector source,
so a different map can't be slipped in by accident. A test checks that it changes nothing else: every layer, its
order and its paint are BombayChitra's.

### `BombayChitraDataset`

Release URLs, `SHA256SUMS` parsing and `Bounds.MMR` (`[72.7, 18.8, 73.85, 19.82]`).

### `RoutingBlobSource`

Where the routing blobs come from. The app uses `AndroidBlobSource` (Android SQLite, reading blobs in 1 MB
`substr()` chunks because Android's `CursorWindow` is limited to 2 MB); tests use `JdbcBlobSource` against a real
`bombaychitra.db`.

## The routing graph format

The graph is BombayChitra's own: the same gzip, little-endian blobs its Go router loads (`server/internal/routing`).
`BombayChitraGraph.load()` reads and validates them the way `graph.go` does: every blob present, lengths
consistent, offsets monotonic, edge targets in range, so a truncated or mismatched file fails loudly with
`RoutingGraphException` instead of producing wrong matches.

| Blob | Content |
|---|---|
| `nodes` | vertex coordinates (lon, lat × 1e7 as int32) |
| `offsets`, `edge_to`, `edge_seg`, `edge_time` | CSR adjacency; `edge_seg` is a segment index, `~s` for the reversed direction |
| `seg_len`, `seg_shape`, `shape` | segment length and geometry (first point absolute, then deltas) |
| `seg_class`, `seg_dir`, `seg_access`, `seg_speed`, `seg_flags` | way class 1–10, one-way, access bits (car 1, two-wheeler 2, foot 4), speed, flags (toll, steps, bridge, tunnel, roundabout, ramp) |
| `seg_name`, `names` | street name index and string table |

For the dataset built on 2026-10-17 that is 197,968 vertices, 247,098 segments and 492,765 directed edges in 13.4 MB compressed.
On top of it the adapter builds a 0.005° grid index of segments for candidate queries (~0.24 ms per query on a
laptop JVM) and runs network distances with a bounded Dijkstra.

## What the layer does not do

- It does not restyle BombayChitra. Nosferatu's overlay is separate `nf-*` layers on top.
- It does not route. BombayChitra's graph is used for map matching and plausibility only.
- It does not fetch anything at runtime except the tiles download the user asks for.
- It does not guess outside coverage. `NoCoverage` turns map matching off; tracking carries on with GPS and motion.

## Updating to a newer BombayChitra dataset

1. Regenerate `graph.db` (`scripts/bombaychitra_assets.py graph --release`) and rebuild; or place a full
   `bombaychitra.db` in the app's map directory (`Android/data/dev.nosferatu/files/bombaychitra/`): it is preferred
   over the bundled graph.
2. Download the new tiles from the Map tab (delete the old ones first).
3. If BombayChitra changed its style, refetch it (`scripts/bombaychitra_assets.py styles`); the style tests will
   fail if the `bc` source disappears.
